# Требования к внешним интеграциям

## 1. Требования к безопасности

- Партнёрская платформа должна получать доступ лишь к минимально необходимому объему данных для выполнения функций, данные пользователей должны быть обезличены.
- Разные сервисы партнёра (домофон, шлагбаум) должны иметь раздельные отдельные учётные записи и разрешения, исключающие доступ к методам других сервисов.
- Биометрические данные и гос номера автомобилей хранятся только в виде векторов и необратимых хэшей, не позволяющих восстановить исходное изображение.
- Каналы передачи данных с партнёром должны быть защищены с использованием TLS 1.2/1.3.
- Партнёр обязан обеспечить шифрование данных на уровне БД и файловых хранилищ, если в его контуре временно сохраняются чувствительные данные.
- Все операции между платформами должны логироваться.

## 2. Протоколы аутентификации и авторизации

- Собственник аутентифицируется в приложении PropDevelopment через существующий механизм (логин/пароль + MFA в перспективе).
- Для делегирования доступа используется протокол OAuth 2.0, токен должен содержать минимальный набор информации.
- Обработка результатов распознавания (подтверждение доступа) должна осуществляться через webhook, подписанный HMAC-SHA256 для проверки целостности и подлинности источника.
- Для критических операций (например, запрос на открытие двери после биометрической верификации) партнёр должен получить одноразовый signed JWT-Token, выданный PropDevelopment, подтверждающий авторизацию для данного события.
- Все секреты, ключи HMAC, сертификаты TLS должны храниться в специализированном хранилище секретов (например, HashiCorp Vault) и регулярно ротироваться.
- Партнёр не имеет доступа к внутренним учётным записям PropDevelopment и наоборот.

## 3. Организация взаимодействия между системами предприятия и внешней платформой

- Взаимодействие строится через API Gateway, который становится единой точкой входа для всех интеграций.
- PropDevelopment передаёт партнёру обезличенные списки разрешений: хэши биометрических векторов и хэши номеров автомобилей, привязанные к идентификаторам устройств (ID домофона/шлагбаума), но без персональных данных.

Пример взаимодействия:
1. Собственник инициирует в мобильном приложении режим распознавания лиц домофоном.
2. Приложение получает от PropDevelopment временный токен доступа.
3. Устройство (домофон) захватывает изображение, выделяет вектор признаков и отправляет его в партнёрскую платформу вместе с токеном.
4. Партнёрская платформа передаёт вектор и идентификатор объекта (домофон) на API Gateway PropDevelopment.
5. API Gateway валидирует токен, проверяет связь пользователя с данным домофоном и отправляет запрос в «biometric-auth-app» для верификации вектора (сравнение с эталонным хэшем в безопасном контуре).
6. Результат (разрешено/запрещено) возвращается партнёру, который исполняет команду открытия. Партнёр не получает информации о личности, только результат верификации true/false.
7. Все шаги логируются с обезличенными идентификаторами.
